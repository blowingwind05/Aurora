# 即时码率

[协议方案](README.md) · [连接与会话授权](connection.md) · [协议验收](verification.md)

Windows 主控可在播放期间下调或恢复已协商预算内的码率。Sunshine 确认活动编码器具备重配置能力后才接受变更。超过本次协商预算时，由现有重协商路径建立新串流。界面分别显示用户请求的网络预算、编码器配置目标和实测接收码率。

## 已接入的会话内版本

当前候选已接入同会话版本校验和明确的超时结果。规则和消息格式见[串流运行时](../streaming.md#即时码率协议初稿)。下文定义下一步的令牌交付与会话绑定。

## 会话绑定提案

提案继续使用已配对 HTTPS 和独立的码率 POST 端点。Sunshine 在现有 `/launch` 或 `/resume` 成功响应中提供可选的 `AuroraVideoBitrateVersion` 和 `AuroraVideoBitrateSession` 字段。播放进程通过已有的子进程输出通道把令牌交给当前会话，采用有长度上限的专用消息。控制进程从其私有输入通道接收令牌，日志、命令行和持久化设置均只保留非敏感信息。

本提案暂缓，主仓继续使用现有码率协议。Sunshine 本地候选通过 `auroraVideoBitrate=3` 启用会话绑定。成功启动的配对 HTTPS 响应和随后建立的加密 RTSP 串流共享本次生成的令牌。会话绑定启用后，旧版状态和设置请求返回 `stale`。

请求使用 `application/x-www-form-urlencoded`，请求体上限 128 字节。状态查询使用 `v=<version>&action=status&session=<session>`。设置使用 `v=<version>&action=set&session=<session>&revision=<revision>&kbps=<kbps>`。沿用候选的规范数字检查，字段顺序和拼写如上。空值、重复或额外字段、超限、溢出和未知版本按无效请求处理。服务端完成配对与会话验证后才进入码率逻辑。

| 字段 | 约定 |
| --- | --- |
| `v` | 会话绑定扩展的协议版本。 |
| `action` | `status` 或 `set`。 |
| `session` | 32 个小写十六进制字符。由 Sunshine 为每次启动生成，查询和设置均需匹配当前会话。 |
| `revision` | 从 0 开始的无符号 32 位整数，采用无前导零的十进制表示。设置必须携带所观察到的版本。版本耗尽时撤销本次会话的码率控制。 |
| `kbps` | 规范十进制整数，范围为 500–150000，实际可设置上限取本次 RTSP 宣告的预算。 |

当前候选使用空请求体和查询参数，由状态查询首次提供令牌。提案将令牌交付移至启动响应，并让查询也携带令牌。该变化与端到端实现一同进入发版验证。[当前客户端协议](https://github.com/blowingwind05/moonlight-aurora/blob/639e79c997beda47126763f3785c14a2ef9a44a6/app/backend/nvhttp.cpp) · [当前被控端协议](https://github.com/blowingwind05/Sunshine-aurora/blob/c6a2b19e8cc1ff1fd909971721b8edbea1d985c6/src/rtsp.cpp)

## 确认与恢复

响应采用 `text/plain`，上限 96 字节。会话内结果返回 HTTP 200。成功响应为 `status <revision> <requested_kbps> <encoder_kbps> <max_kbps>` 或同格式的 `applied`，其余会话内结果只返回表中的单词。输入无效返回 HTTP 400，客户端证书无权调用时返回 HTTP 403。旧端点缺失的 HTTP 404 仅在固定证书校验成功后解释为缺少能力。

| 结果 | 被控端行为 | 主控行为 |
| --- | --- | --- |
| `status` | 返回最近确认的请求预算、编码器目标、协商上限和当前版本。 | 更新本次串流显示。仅查询到状态时保留用户已保存的偏好。 |
| `applied` | 相关会话的编码线程确认新目标后返回新版本和确认值。 | 核对会话、版本和目标，提交本次偏好变更。 |
| `busy` 或 `pending` | 当前有操作在执行，或操作已进入驱动而等待到期。允许再次查询。 | 保持当前播放，查询结果前暂缓再次提交或重连。 |
| `stale` | 当前会话或版本已变化，拒绝执行。 | 清理过期状态。只在当前播放进程仍获授权时刷新。 |
| `rejected` 或 `failed` | 请求超出协商预算，或驱动拒绝目标。保留上次确认值。 | 保持播放并展示原因，保留已保存偏好。 |
| `unsupported` | 已验证的旧宿主缺少端点，或宿主明确报告当前编码器缺少能力。 | 说明需重协商。用户选择继续后使用现有同窗口重连流程。 |
| `unavailable` 或传输失败 | 编码器重建返回暂不可用。证书失败和网络超时由客户端保留各自的错误类型。 | 重新检查或结束当前授权，保持正在播放的画面。 |

每个会话只允许一个变更待处理。Sunshine 在受保护的会话状态中比较并递增 `revision`，再将获准操作交给编码线程。同一个旧版本的请求在后续变更被接受后只能得到过期结果。驱动调用超时后仍可能完成。此时查询以新会话状态为准，主控以远端确认值作为当前值比较，用户再次选择原先保存的值时仍可发起合法变更。只有与用户操作对应的确认结果才提交设备偏好。

## 复用编码与重协商

主仓候选已让初始协商与即时调整共用 Sunshine 的 FEC、音频和包开销计算。保留既有宿主码率上限，并覆盖两条路径应用同一预算的结果。待执行的目标由既有 NVENC 动态 CBR API 在编码线程应用。当前确认目标随编码器重建恢复，新的 RTSP 串流重新建立预算和控制授权。

沿用 Windows 同窗口重协商及回退逻辑。隐私状态未确认、遮罩开启或退出串流会停止远端应用时暂缓重协商。macOS 和旧版播放组件继续走已支持的连接与设置流程。版本能力从现有运行时探测和已配对启动响应读取。经过证书验证的旧版 404 可以表达缺少端点，其他网络错误、异常响应和未知版本按各自的失败状态处理。
